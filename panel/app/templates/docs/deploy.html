What it does

Push your code to GitHub or GitLab, then click Deploy now on the site's page (or let a push do it for you). The panel pulls the latest commit of your branch into the site's folder, runs your deploy script, and restarts whatever needs the new code. Every deploy runs as a job with a live log and is kept in the site's deploy history.

It deploys in place: the code folder is a normal git checkout. Files that are not in git (.env, vendor/, node_modules/, uploads in storage/) are never touched.

Setting it up

  1. Open the site and find Deployment. Enter the repository URL and branch.
    • Private repository: use the SSH URL, like git@github.com:you/app.git.
    • Public repository: an https:// URL also works. Do not put a username or password in the URL.
  2. Check the code folder. The default is the project folder: the folder above public for Laravel, the app folder for Node.js and Python.
  3. Pick a deploy script preset or write your own, then click Save and set up.
  4. For an SSH URL the panel shows a deploy key. Add it once to the repository: GitHub → Settings → Deploy keys → Add deploy key (leave write access off). GitLab: Settings → Repository → Deploy keys. The key only lets this server read this one repository.
  5. Click Deploy now.

On the first deploy an empty folder is cloned into. A folder that already holds your site (for example one uploaded by FTP) is connected to git in place: files that are in the repository are updated to the repository's version, everything else is left as it is.

The deploy script

Runs after every pull, in the code folder, as the site's own user (never root). One command per line; the deploy stops at the first command that fails, and the log shows each command with a + in front of it. {PHP} is replaced by the site's PHP binary.

PresetScript
Laravelcomposer install --no-dev --optimize-autoloader --no-interaction
{PHP} artisan migrate --force
{PHP} artisan optimize
PHP with Composercomposer install --no-dev --optimize-autoloader --no-interaction
Node.jsnpm ci
npm run build --if-present
Python[ -d .venv ] || python3 -m venv .venv
pip install -r requirements.txt
Static(nothing)

After the script the panel restarts the Node.js / Python app if it is running, restarts running workers (queue workers keep old code in memory), reloads PHP-FPM (which clears OPcache) and makes sure nginx can read new files. You do not need to add those steps.

ComposerThe Laravel and PHP presets need composer; install it from Stack if the log says it is missing.

Auto-deploy on push

  1. Under Auto-deploy on push click Turn on. The panel shows a Payload URL and a Secret.
  2. GitHub: repository → Settings → Webhooks → Add webhook. Paste the URL, set content type to application/json, paste the secret, keep "Just the push event". If the panel uses its self-signed certificate, set SSL verification to disabled.
  3. GitLab: Settings → Webhooks. Paste the URL, put the secret in Secret token, tick Push events.

Only pushes to the configured branch deploy; other branches are ignored. Requests without a valid signature are refused, so the URL alone is not enough to trigger a deploy. New URL and secret replaces both if they ever leak. The panel must be reachable from the internet on its port (8443) for GitHub to call it.

History and rollback

Each deploy is listed with its commit, message, trigger (manual, webhook or redeploy), who started it, how long it took and a link to its full log. Redeploy on an older successful deploy checks out that exact commit and runs the script again, which is a one-click rollback. The next normal deploy goes back to the latest commit of the branch.

Database migrations are not undone by a rollback; roll those back yourself if needed.

If a deploy fails

  • Fetching from the repository failed: the deploy key is not added to the repository (or was added to a different one), or the URL or branch is wrong.
  • The deploy script stopped: the last command in the log is the one that failed, with its error above it.
  • Permission denied in the script: a file in the code folder is owned by root (for example created with sudo). Fix ownership in the file manager or the terminal.

Disconnect repository only forgets the settings; the code, its .git folder and the history stay.
