What it is

The Terminal is a real shell on the server in your browser, so you can run git, composer, npm, php artisan, tail -f and so on without a separate SSH client. It supports full-screen programs such as vim, htop and less, and resizes with the window.

Log in as

The Log in as menu at the top picks which account the shell runs as:

ChoiceYou get
A site (domain (site_user))A shell as that site's user, starting in its folder. It can only touch that site's files, which is what you want for deploying code, running composer install, npm, migrations and queue workers.
root (last in the list)Full control of the server: install packages, edit system files, restart services. Use deliberately.

Changing the menu opens a fresh shell as the new account. The terminal opens as root by default, except when you arrive from a site's Terminal button, which opens as that site's user.

Prefer the site userFiles created while logged in as root are owned by root, and the website then cannot write to them. Working as the site user avoids that whole class of permission problem.

Behaviour and limits

  • The session closes after 20 minutes without input. Reload the page to start a new one.
  • Closing the tab ends the shell and everything started from it. For long-running work use a tool such as tmux, a cron job, or a managed application service.
  • The shell does not inherit the panel's secret settings.
  • Opening and closing a terminal, and which account was used, are recorded in the audit log.

Security

Only a logged-in panel administrator can open a terminal, and the connection only accepts requests from the panel's own page. Treat panel access like root access to the box.
