Overview

Browser ──HTTPS :8443──▶ nginx ──▶ lite-panel (uvicorn, 127.0.0.1:8765)
                          │             └─ SQLite database, job worker
                          └──▶ Adminer (php -S, 127.0.0.1:8766), behind the panel login

Visitors ──:80/:443──▶ nginx ──▶ PHP-FPM pool per site  (PHP sites)
                              └─▶ 127.0.0.1:<port> app   (Node.js / Python sites)

The panel is a small Python (FastAPI) application. It never binds a public port: nginx terminates TLS, enforces the login in front of Adminer, and proxies to the panel on loopback.

Design principles

  • The database is the source of truth. Configuration files the panel owns (nginx hosts, PHP pools, services) are rendered from its database and can be rebuilt at any time. The panel only writes files it owns, using its own lite-panel- names, and never edits vendor config in place.
  • Atomic writes. Files are written to a temporary file and renamed, so a crash cannot leave a half-written config.
  • Nothing is hidden. Everything the panel does is ordinary package installs, config files and systemd units you can inspect and change.
  • Discovery, not guessing. Available PHP and Node.js versions come from the system at runtime.
  • Isolation per site. Each site has its own system user, folder permissions and PHP pool or application service.

Security

  • Every user-supplied value goes through strict validators before it is used.
  • Every system command is run as an argument list, never through a shell string, so input cannot become a command. (The web terminal is the one deliberate exception and is only available to a logged-in admin.)
  • Adminer is reachable only with a valid panel session and is pinned to the local MariaDB.
  • The panel sends strict security headers (HSTS, X-Frame-Options: DENY, X-Content-Type-Options, a Content-Security-Policy).
  • Forms are protected by CSRF tokens; sessions expire after 12 hours; five failed logins lock the account for 15 minutes.
  • Database, FTP and generated SSH private-key passwords are shown once and not stored.
  • Application environment variables are kept in a root-only file.
  • Sensitive actions are recorded in an audit log.

Scope (what it is not)

  • Nginx only (no Apache).
  • Single administrator account (no roles).
  • No email / SMTP management.
