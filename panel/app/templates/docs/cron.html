For processes that must run continuously (queue workers, Horizon), use Workers instead of cron.

What cron jobs are

A cron job runs a command on a schedule: clearing caches, running a Laravel scheduler, importing feeds, sending reports. The Cron page manages them without editing crontab by hand. The panel owns the schedule: it regenerates each user's crontab from its own list, so what you see is what runs.

Who it runs as

ChoiceRuns asUse for
A site (domain (site_user))That site's unprivileged userAnything about the application: php artisan schedule:run, scripts in the site folder. Prefer this.
Server (root)rootServer-wide maintenance only (package updates, system backups). It has full access to everything.

Creating a job

  1. Click + New cron job.
  2. Choose Runs as, an optional description, and the Schedule: pick a preset (every minute, every 5 minutes, hourly, daily, weekly …) or Custom to enter the five cron fields (minute, hour, day of month, month, weekday).
  3. Enter the command and save.

Examples

GoalScheduleCommand
Laravel schedulerEvery minutecd /var/www/shop && php artisan schedule:run >> /dev/null 2>&1
WordPress cronEvery 5 minutescd /var/www/blog && php wp-cron.php
Node script nightlyDaily 02:00cd /var/www/app && node scripts/cleanup.js

Use full paths and cd into the project first: cron runs with a minimal environment.

Managing jobs

  • Edit a job's schedule, command or description.
  • Enable / disable without deleting it.
  • Delete it. Deleting a site also removes its jobs.
The cron service must be installed on the server. The page warns you when it is not; jobs are saved but do not run until it is.
