Why keys

An SSH key pair replaces a password: the private key stays on your computer and the server only holds the public key. It is far harder to attack than a password. Once keys work, you can turn off password logins for SSH (see Fail2ban for why that matters).

Which account a key is for

Keys are attached to a system account: root (full server administration) or an individual site user (site_<name>). A site-user key lets a developer connect as ssh site_name@server and land in that site's folder with no access to other sites. Giving a site user a key also lets that account log in over SSH with a normal shell.

Generate a key pair on the server

  1. Open SSH, choose the account and the key type (Ed25519 is recommended; RSA 4096-bit is available for older systems), then click Generate SSH key pair.
  2. Download the private key when it is offered. It is shown once and not kept by the panel. Save it somewhere safe.
  3. On your computer restrict the file and connect: 
    chmod 600 my-key.pem
ssh -i my-key.pem root@server-ip   # or site_name@server-ip

Import an existing public key

If you already have a key (~/.ssh/id_ed25519.pub on your computer, shown with cat ~/.ssh/id_ed25519.pub), paste its contents under Import existing public key. This is the best option: your private key never leaves your machine, and you only paste the public half. Afterwards connect with ssh user@server-ip.

Generate or import?

Choose Generate to have the panel create a brand-new pair for you (the private key is downloaded once). Choose Import if you or a teammate already have a key pair.

Authorized keys

The list shows every key the panel manages with its fingerprint. View the public key, or delete a key to revoke that access immediately.

Locked out?Keys are added to the account's authorized_keys. If you lose the only key, log in through the provider's console and fix it there.
