How it works

A PHP site is "files served by PHP-FPM". A Node.js or Python application is different: it is a long-running process that listens on a local port. Two pieces make that production-ready, and the panel manages both:

  1. A systemd service (lite-panel-app-<site>.service) runs your start command in the background as the site's own unprivileged user, restarts it if it crashes, and starts it at boot.
  2. An nginx reverse proxy receives requests for your domain on ports 80/443 and forwards them to 127.0.0.1:<port>, including WebSocket connections. HTTPS, the www redirect and custom nginx rules work exactly as for other sites.

The application itself never listens publicly; only nginx does.

Before you start

  • Install the runtime from Stack: Node.js (pick a major version) or Python (installs venv, pip and build tools). The New site form tells you when one is missing.
  • Your app must listen on the port given in the PORT environment variable (the panel also sets HOST=127.0.0.1). For Python, put {PORT} in the start command.

Creating an application site

  1. Sites → New site, enter the domain, set Site type to Node.js application or Python application.
  2. Choose a start command preset (or type your own). Leave the port blank to have one assigned (3001, 3002, …).
  3. Optionally add environment variables, one KEY=value per line.
  4. Click Create site. The service and proxy are set up but not started yet, because there is no code to run.

Deploying your code

  1. Upload the project to the site's app folder (shown on the site page, normally /var/www/<site>) with the file manager, FTP, or git clone in the terminal.
  2. On the site page click Install dependencies.
    • Node.js: runs npm ci when package-lock.json exists, otherwise npm install. Tick Also run npm run build for frameworks that need a build step (Next.js, NestJS, …).
    • Python: creates a virtualenv at .venv in the app folder and runs pip install -r requirements.txt. Each app has its own packages, so two apps never conflict.
  3. Click Start. The panel waits a couple of seconds and checks that the process stayed up; if it crashed immediately you see the log lines that explain why.
  4. Visit your domain.

After uploading new code, run Install dependencies again if the packages changed, then Restart.

Controls

ActionWhat it does
StartEnables the service (so it also starts at boot) and starts it.
RestartRestarts the process. Use after deploying code or changing settings.
StopStops it and disables it, so it stays off after a reboot.

The status badge shows running or stopped and refreshes by itself.

Application settings

  • Start command — run from the app folder under bash. {PORT} is replaced by the port; $PORT also works. Presets cover common setups.
  • Port — 1024–65535, unique per site; a few ports used by other services are reserved.
  • Environment variables — written to a root-only file (/etc/lite-panel/apps/<site>.env). PORT and HOST are managed by the panel and cannot be overridden. Node.js apps also get NODE_ENV=production and Python apps PYTHONUNBUFFERED=1 unless you set your own.

Saving restarts a running app so the change takes effect.

Gunicorn and Uvicorn must be listed in your requirements.txt so Install dependencies puts them in the virtualenv.

Logs and troubleshooting

The Application logs panel on the site page shows the service's recent output (also under Logs). Typical problems:

  • 502 Bad Gateway: the app is stopped or crashed. Check the status badge and logs; start it.
  • App exits right after Start: usually a missing dependency or a wrong start command. The error is shown in the job log.
  • App runs but the page is wrong: make sure it listens on 127.0.0.1 and the assigned port, not a hard-coded one.
  • Command not found: Node tools in node_modules/.bin and Python tools in .venv/bin are on the service's PATH; install dependencies first.

Good to know

  • The site type cannot be changed after creation.
  • Node.js runs one major version system-wide (switching it on the Stack page affects all Node sites).
  • The service runs as the site's user with NoNewPrivileges and a private /tmp.
  • Deleting the site stops and removes its service.
  • For a React / Vue / Angular front-end that is just built files, choose a PHP / static site with PHP set to None instead; no service is needed.
