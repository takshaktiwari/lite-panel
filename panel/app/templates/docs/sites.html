What a site is

A site is one domain with everything it owns, created together and removed together:

  • a dedicated system user named site_<name> (the real isolation: one site cannot read another's files);
  • a folder at /var/www/<name>, readable only by that user (mode 750);
  • an nginx virtual host;
  • for PHP sites, its own PHP-FPM pool running as that user, on the PHP version you chose;
  • for Node.js and Python sites, a systemd service and a reverse proxy (see Node.js & Python apps);
  • optional background workers such as Laravel queue workers (any site type);
  • optionally an FTP login, SSH keys, cron jobs, databases and backups linked to it.

Creating a site

Open Sites → New site.

FieldMeaning
DomainThe hostname, e.g. example.com or blog.example.com. Lowercase letters, digits and hyphens.
Website folderWhere the files live, under /var/www/. Optional: left blank it is derived from the domain. Type example/public to serve from a public subfolder while the site itself stays at /var/www/example.
Site typePHP / static (Laravel, WordPress, plain HTML, React/Vue builds), Node.js or Python application.
PHP versionPHP / static sites only. Choose None for pure static content.
Redirect wwwSend www.example.com to example.com (on by default).
Enable HTTPSTry to get a certificate right away. If DNS is not ready yet, the site is still created over plain HTTP and you can enable HTTPS later.

Creating a site runs as a job. A placeholder page is written for PHP / static sites so you can confirm it works.

The site page

Click a domain in the Sites list. The page shows:

  • Overview — system user, home directory, disk usage, webroot, SSL state, with shortcuts to the file manager, logs and a terminal as that site's user.
  • PHP version (PHP sites) or Application controls (Node.js / Python).
  • SSL, DNS propagation, Databases, Backups, Cron jobs, FTP, SSH access and Delete site.

Changing the PHP version

Pick another installed version and click Apply. The panel removes the old pool, creates a new one on the new version and restarts PHP-FPM. Different sites can run different versions side by side. Install more versions on the Stack page.

Document path (webroot)

The pencil icon next to Webroot changes the folder nginx serves. It must stay inside the site's home directory. Typical values:

  • Laravel: /var/www/shop/public
  • WordPress / plain PHP: the site folder itself
  • React / Vue build: the folder containing index.html
  • Node.js / Python: the folder the application runs from (the "App folder")

HTTPS (SSL)

  1. Install SSL (Let's Encrypt) from the Stack page (once per server).
  2. Make sure the domain's A record points at this server.
  3. On the site page click Enable HTTPS, optionally giving an email for expiry notices.

The panel requests the certificate through the webroot challenge, switches the site to HTTPS and redirects HTTP to it. Certificates renew automatically, and the site page shows the expiry date. If www has no DNS record yet, the certificate covers only the bare domain; the panel notices this and keeps www as a plain redirect. Disable HTTPS turns it off but keeps the certificate.

Checking DNS

Check DNS propagation asks several public resolvers what the domain resolves to and compares it with this server's public IP, so you can tell whether a certificate request will succeed.

Deleting a site

Type the domain to confirm. By default files are kept on disk and linked databases are detached, not dropped (they stay on the Databases page). Tick the boxes to delete files and/or databases as well. Deleting removes the nginx config, the PHP pool or application service, the FTP login, cron jobs and the system user.

Not recoverableDeleting files or databases cannot be undone. Take a backup first.

Custom nginx rules

Each site includes an override file the panel never overwrites. Edit it from the Config editor to add rewrites, headers or cache rules.
