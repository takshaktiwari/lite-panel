I can't open the panel

  • Use the public IP. The installer may print a private address (10.x, 172.16–31.x, 192.168.x) that only works inside the cloud network. Use https://PUBLIC-IP:8443/.
  • Open port 8443 in the cloud firewall (AWS security group, etc.) and, if UFW is active, on the server too. A timeout means a firewall; "connection refused" means nothing is listening.
  • Browser certificate warning is normal (self-signed). Choose Advanced → Proceed.
  • On the server: sudo systemctl status lite-panel nginx and sudo journalctl -u lite-panel -n 50.

I lost the admin password

sudo lite-panel reset-password --username admin

Only one PHP version is offered

See Stack → PHP versions. It is almost always an OS release the third-party PHP repository does not support yet.

A site shows an error

SymptomLikely cause and fix
502 Bad Gateway (PHP)PHP-FPM is down or the site's PHP version was removed. Change the site's PHP version or reinstall it on Stack.
502 Bad Gateway (Node/Python)The app is stopped or crashed. Open the site page, read the application logs, fix, then Start.
403 ForbiddenWrong document path, missing index file, or permissions. Check the webroot and file modes.
404 on every page except /The framework needs its front controller; make sure the document path points at public (Laravel) and the site is PHP.
413 Request Entity Too LargeUpload exceeds the limit. Raise client_max_body_size in the site's nginx override and PHP's upload_max_filesize/post_max_size.
"Permission denied" in the appThe folder is not writable by the site user. Fix ownership/permissions (and avoid doing file work as root).

Always check Logs first; the cause is usually stated there.

HTTPS won't issue

  • The domain's A record must already point at this server (use Check DNS propagation).
  • Ports 80 and 443 must be open in both firewalls; Let's Encrypt connects to port 80.
  • Let's Encrypt limits repeated requests per domain; wait and retry.
  • The site is still served over HTTP; you can retry Enable HTTPS any time.

A job failed

Open it from Jobs and read the last lines: they state the cause (missing package, DNS, invalid value). Fix it and run the action again; jobs are safe to repeat.

FTP connects but listing hangs

The passive ports are blocked. Open TCP 30000–30100 in the cloud firewall and UFW (see FTP).

Locked out of SSH

Use your provider's web console to log in, then check Fail2ban bans (sudo fail2ban-client status sshd) and the firewall (sudo ufw status).

Config seems out of sync

Run Rebuild on the Stack page or sudo lite-panel rebuild to regenerate everything from the database.
