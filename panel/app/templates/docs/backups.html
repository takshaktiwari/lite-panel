What a backup contains

A backup is one compressed archive (.tar.gz, gzip level 9) for one site, holding:

  • files/ — the site's whole folder;
  • db/<database>.sql — a SQL dump of every database linked to the site.

You can include files, databases, or both. Archives are stored on the server in /var/backups/lite-panel/<site>/ and named like shop_full_2026-10-27_0200.tar.gz.

Backups on the same server are not disaster protectionIf the server is lost, so are its backups. Download important archives regularly, or copy /var/backups/lite-panel off the server.

Creating a backup now

  1. Open Backup (or the Backups section of a site's page).
  2. Choose the site and what to include, then run the backup. It runs as a job.

Scheduled backups

Create a schedule to back a site up automatically:

SettingOptions
FrequencyDaily, twice daily (every 12 hours), weekly (pick the day), monthly (pick the day of month)
TimeHour and minute, in UTC
IncludeFiles and/or databases
KeepHow many archives to retain (default 7). Older ones are deleted automatically after each run.

You can pause a schedule, run it immediately, or delete it. The next run time is shown for each schedule.

Downloading and deleting

The Backup Archives list shows size and date for each archive, with Download and Delete.

Restoring

Restoring is deliberately manual so nothing is overwritten by accident:

  1. Download the archive (or use it in place on the server).
  2. Extract it: tar -xzf shop_full_2026-10-27_0200.tar.gz in a scratch folder.
  3. Copy what you need from files/ back into the site folder.
  4. Import db/<name>.sql through Databases → Import or Adminer.
