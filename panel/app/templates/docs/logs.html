The Logs page shows the most recent lines of the server's logs, so you can debug without SSH.

What you can read

SourceUse it to…
Nginx error / access log (server-wide)See request failures and traffic.
Site logs (pick a site)Per-site nginx error and access logs, and the PHP error log for PHP sites. First stop for a 500 error.
Application service (Node.js / Python sites)Output of your app: crashes and stack traces. Also shown on the site page.
MariaDB journal and slow-query logFind database errors and slow queries.
FTP server logCheck logins and transfers.
Lite-panel logsThe panel's own log, its nginx error log and its service journal.

Using the viewer

  • Lines — choose how many of the latest lines to load.
  • Filter — type text to keep only matching lines (for example an IP address or 500).
  • Auto-refresh — tail the log live while you reproduce a problem.

Only a fixed list of log locations can be read, so the page cannot be used to open arbitrary files.

Debugging recipes

  • White page / 500 on a PHP site: site → PHP error log.
  • 502 / 504: nginx error log for the site; for apps, the application log and that the service is running.
  • Certificate won't issue: check DNS and the nginx error log, then retry Enable HTTPS.
