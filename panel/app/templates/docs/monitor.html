The Monitor page answers "is the server healthy and what is using it?" without logging in over SSH.

Live metrics

Updated every few seconds:

  • CPU — overall use, core count and load average. Sustained load above the core count means the server is saturated.
  • Memory — used versus total RAM (and swap). Frequent swap use means you need more RAM or fewer processes.
  • Disk — used space on the main volume.
  • Network — current download and upload speed.

Historical usage

The panel records lightweight snapshots in the background and keeps 7 days of history, shown as charts. Use it to find out when a slowdown happened.

Disk usage breakdown

Shows storage by category and the largest directories, so you can find what is filling the disk (usually logs, backups or uploads). The scan runs in the background and may take a moment on large disks.

Top processes

A live list sorted by resource use. You can kill a runaway process from here. Killing system processes can break the server, so only stop what you recognise.

Common uses

  • Site suddenly slow: check CPU and memory, then the top processes (often a stuck PHP worker or a heavy script).
  • Disk full: open the disk breakdown, then clean logs or old backups.
  • Choosing a server size: watch a week of history before upgrading.
